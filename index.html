Your real browser. A second operator.

Amplifier Browser Bridge lets an AI agent read and act inside your actual, logged-in Microsoft Edge session -- on this device, or on a completely different one, over your own Tailscale network. It is not a disposable automation browser; it is the browser you already use.

Install View on GitHub
Early-stage, not yet published to any extension store. Phases 1-5 of a 6-phase build are complete (hub, extension, addressing, agent surfaces, policy engine); CDP escalation (trusted input, background-tab screenshots) is not yet built. This is a sideload-only project today -- see INSTALL.md for the real, harder-than-usual install path.

What this is not

No vendor product does cross-device browser co-working today. Claude in Chrome, Edge Copilot Mode, Gemini in Chrome, and Playwright's own MCP extension mode all run their control plane on the machine the human is sitting at. This project's whole reason to exist is driving the browser on a device you are not sitting at, from one you are.

The nearest prior art that already does cross-device control is browser-relay (MIT) -- it authenticates a public Cloudflare Worker relay with a bearer Device ID that its own documentation calls "a capability -- anyone with it can control this browser." This project's honest differentiator is not being first; it is replacing that relay with your own tailnet: no third-party relay in the path, no long-lived bearer token traveling the public internet, and device-level network ACLs you control. See the design doc's positioning section for the full comparison.

Install

There is no store listing. Installing this today means three pieces working together: a hub process, this extension, and a shared token. Read INSTALL.md in full before you start -- it is written for someone who has never seen this system.

1. Run the hub

uv tool install amplifier-browser-bridge, then amplifier-browser-bridge init.

2. Load the extension

Download the latest release zip, unzip it, and Load unpacked at edge://extensions/.

3. Configure and confirm

Paste the hub URL and token into the extension's options page, then run amplifier-browser-bridge doctor.

Security posture

This software controls a real, authenticated browser session. Read SECURITY.md in full before installing or deploying it. The summary below is not a substitute.
  • The per-device shared token is the load-bearing boundary for most deployments -- not your tailnet. Tailscale's own default ACL policy lets every device on your tailnet reach every other device on every port.
  • The hub binds 127.0.0.1 by default; a wildcard bind is never silent -- it prints a named warning every time.
  • Consent is enforced structurally at one choke point in the hub, not by asking the model to behave -- see docs/POLICY.md for exactly what the denylist and confirmation gates do and do not catch.
  • Every command, decision, and result is written to an audit log.

Permissions

This is a broad-access-by-default tool, not a narrow, single-site extension -- its permissions say so honestly rather than minimizing them. Full long-form reasoning, including which of these could and could not be honestly narrowed, lives in docs/permission-justifications.md.

Permission Why
<all_urls> The agent can be asked to act on any site you browse to -- the maintainer's explicit design goal, not an oversight.
debugger Optional escalation for trusted input events and background-tab screenshots. Not used unless a command asks for it.
scripting, tabs, webNavigation Read pages, dispatch clicks/typing, know what tabs/URLs exist.
storage Stores the hub URL/token you configure and this device's own identifier.
downloads, alarms, tabGroups Support specific commands (download claiming, keepalive, tab-group-aware addressing).
