Browser Bridge ships 7 operation-enum tools (`browser_devices`, `browser_tabs`, `browser_page`, `browser_capture`, `browser_download`, `browser_archive`, `browser_admin`): address explicitly every time -- `browser_devices(operation="list")` for a `device_id`, then `browser_tabs(operation="list")` for a `tab_id`, then `browser_page(operation="snapshot")` for element refs, with no implicit "current" device or tab; a command to a non-live device returns `{"status": "queued", command_id, ...}` instead of `{"ok": ...}`, which is normal and actionable rather than an error or a hang, and `browser_devices(operation="poll")` collects the real result later; configuration comes from the session environment, `AMPLIFIER_BROWSER_BRIDGE_HUB_URL` (default `ws://127.0.0.1:8900/agent`; point it at the hub's Tailscale IP, never a MagicDNS name) and `AMPLIFIER_BROWSER_BRIDGE_TOKEN`, and the full vocabulary -- including the map from the 31 former flat tool names to their `(tool, operation)` pairs -- is in `docs/AGENT_SURFACES.md`, `docs/DECISION_GUIDE.md` and `docs/PROTOCOL.md`.
